# apps/game/

The Phaser client. It renders PILOT's world and hosts the WebMCP tool director. It is a **view**, not an authority.

## Local rules

- **The client never possesses the solution.** It renders `projectForPilot` deltas pushed over the WebSocket and nothing else. No `HIDDEN` field, no puzzle answer, and no server-side derivation ever ships to the browser. If a feature seems to need one, the feature is wrong.
- **Puzzle-critical visuals render to canvas, never to DOM.** There must be no text node holding a glyph, a needle value, or a cipher offset. The one deliberate exception is the accessibility mirror, which ships behind an explicit toggle and is documented as a trade-off.
- **The console is DOM and the room is canvas, and a panel moves out only after it is checked against that rule one at a time** (D-036). A readout may be DOM for exactly three reasons: it is public copy, it is something KEEPER can obtain for itself, or it is `SHARED`/`AUDIBLE` by construction. `ui.ts`'s header carries the audit; extend it rather than reasoning afresh.
- **All spec contact lives in `src/webmcp/adapter.ts`.** Nothing else in this app may touch `document.modelContext` or `navigator.modelContext`. Feature-detect `document` first, then `navigator`. A grep for `modelContext` that returns any other source file is a defect.
- **Tools are authored as data plus a `run` that returns a string** (`src/webmcp/tool.ts`). The spec's result envelope, the timing, and the never-throw-at-an-agent rule are applied once, by the director's instrumentation wrapper. A tool module never builds a `content` array.
- **Where a tool is registered may change; when it exists may not** (D-033). With `VITE_ARCHIVE_ORIGIN` set, `read_manual` and `read_station_log` are registered by a hidden cross-origin frame rather than by this page, and the director tells that frame which of them should exist right now. The tier tables stay the one place that decides lifetime. Both paths ship green, and the fallback is the default until delegation is verified in ChatGPT's in-app browser.
- **The manifest plate must ask for the archive origin's tools by name.** A default `getTools()` does not include a frame's tools even when both delegation gates are satisfied (doc 11 section 4), so `listToolNames` takes `fromOrigins`. A plate that under-reports KEEPER's faculties is worse than no plate, because the plate exists to prove the animation is not a lie.
- **The registry follows the server, never a guess** (D-021). `ToolDirector.applyState` is the only thing that mounts or tears down a tier, and it reads the machine state the worker put on the response. Nothing infers a chamber from what it just called.
- **No WebMCP means the gate screen, never a throw.** For some judges that screen is the entire submission. It carries the pitch, the mark, the ablation chart, SPECTATE, and setup steps for both browsers.
- **`toolchange` drives the UI from real registry state.** The manifest panel and KEEPER's body both render from an actual `await getTools()` call inside one listener. Never from a parallel guess about what was just registered. The panel exists to prove the animation is not a lie.
- **Colour is information architecture, and it never bends for a nice frame.** Amber: only PILOT perceives this. Cyan: only KEEPER perceives this. Bone-white: both. `AUDIBLE` is bone-white with a double ring. Every channel-coded element also carries its shape marker, because colour alone must never carry information.
- **The palette is locked at 14 colours** (doc 06 section 2). Adding a fifteenth is a decision-log entry, not a judgement call. There is no green: success is a bone-white flash and a shape change.
- **Native resolution is 320x320, integer scaling only** (D-031). Fractional scaling produces half-pixel shimmer that reads as carelessness. The canvas is twenty 16px tiles square, the mount point is pinned to 640 because the scale manager snaps to multiples of 320, and **the frame around the stage is a separate element**: Phaser measures its parent's border box, so a border on the element it mounts into is a border it cannot see and it lands on a fractional scale (D-036).
- **The station is one room seen from above, and a room does not know where it is** (D-035). `room.ts` emits tile coordinates local to a chamber's own interior; `scenes.ts` centres it. A chamber that reached for an absolute canvas constant could not be resized. Which rooms the session has and which one the pair is in is progress, not geometry, and lives in `floors.ts` and the console.
- **A door is contiguous and the row under it belongs to its caption.** Three leaves spread evenly across four tiles is a doorway with a pillar in it. Captions are centred under their tile, are routinely wider than it, and are clamped to the room by `scenes.ts` from the text object's measured width - never by choosing safer columns per chamber.
- **The warm reference is taken for composition, never for hue.** Amber reads as "only PILOT perceives this" only against a cold neutral ground. **Decoration that competes is not decoration.** Floor plates carry meaning only where they say "this is the way out"; a pattern near the mechanism is one more rectangle for the eye to check, in a game whose whole task is finding the channel-coded object.
- **Greybox before art.** Every chamber ships as flat rectangles in palette colours and is playtested before a single final sprite is drawn.
- **The room's art is the vendored pack and the channel picks the directory** (D-034, superseding D-029's no-asset-files rule). `public/art/{pilot,keeper,shared}/` is yellow, blue and hue-stripped neutral, one per channel, so a device cannot take a colour without taking the meaning that goes with it and there is no `setTint` anyone can forget. Every path and frame count lives once in `render/atlas.ts`; `scripts/check-art.mjs` fails the build when the table and the files disagree, because a wrong frame count does not throw, it renders looking merely a bit off.
- **The pack's licence is not this repository's licence.** MIT covers the code and not `public/art/`. Use in the game is permitted, redistribution is not. Adding, removing or modifying a file there means updating `public/art/CREDITS.md` in the same commit.
- **The glyphs and the two bodies stay authored as pixels in `render/sprites.ts`.** One character per pixel, mapped to a `PALETTE` key. They carry meaning no pack could know: the glyphs are the shapes PILOT has to describe and `wave` and `knot` are deliberately confusable, PILOT must not be amber, and KEEPER must not have eyes.
- **A glyph's name is KEEPER's half of the split and never appears on PILOT's side.** A lever captioned "spiral" deletes the chamber, because reading a label aloud is not describing a shape. Pieces carry the lever's position or the key's number - what KEEPER can be told to act on - and wear the glyph as a drawing.
- **`write_note` is declarative and `read_note` is imperative, and that is the rule, not an inconsistency** (doc 03 section 8, D-028). Declarative for a tool that is a form the human can also submit; imperative for pure agent capability. A declarative tool leaves the registry only when its element leaves the DOM, so the director owns that element and the ending needs both mechanisms.
- **Phaser is imported dynamically, in `render/station.ts`, and nowhere else** (D-026). It is 358KB gzipped against a 400KB budget, and the gate screen must never fetch it. A static `import ... from "phaser"` anywhere else undoes that silently; `scripts/check-bundle.mjs` fails the build when it does.
- **What a frame contains is decided in `render/room.ts`, `render/floors.ts` and `render/hud.ts`, which are pure.** The scenes only paint. Anything that can be decided without a canvas is decided there, because that is the half that can be wrong in a way nobody notices by looking, and it is the half with tests.
- **KEEPER is drawn in the wall, never on the floor.** It is not in the room: it is behind the station's panels, reaching into every cavity at once. They can see each other and reach each other nowhere, and a frame standing on the floor is a mechanism PILOT could walk to.
- Tool descriptions are agent-facing UI copy. Budgets are 500 characters per description, 150 per parameter description, 30 per name, 1500 per output, and they are enforced by `src/webmcp/budgets.test.ts` over the tool objects rather than by a lint rule over the source (D-022). That test also pins the annotations, so adding a tool means adding it to the mutating or untrusted-content list there, deliberately.
